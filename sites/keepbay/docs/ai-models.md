# 模型设置 {#ai-models}

Keepbay 的 AI 功能用什么模型、在哪里运行，都在「系统设置 › AI 模型」中设置。这个页面只有所有者能看到，属于专业版。

模型有两种来源：在这台设备上运行的本地模型，以及您添加的厂商，比如家里的 Ollama 或者云端的 DeepSeek、通义千问。

## 先配哪些 {#quick-start}

不同的功能要不同的模型：

| 功能 | 需要的模型 | 可以用 |
|---|---|---|
| [语义搜索](./semantic-search) | 文本向量 | 本地模型，或云端的向量模型 |
| [按画面搜图](./semantic-search#by-image) | 图文向量 | 只能用本地模型 |
| [识别图中文字](./semantic-search#ocr) | 文字识别 | 只能用本地模型 |
| [AI 桌面](./ai-desk) | 对话 | Ollama 等局域网模型，或云端模型 |
| [自动整理](./inbox) | 对话 | 同上 |
| [AI 标签](./ai-tags) | 对话 | 同上 |
| [日期提醒](./reminders) | 不需要模型也能用规则找；对话模型可选，用来核对 | 图片要先识别出文字 |

我们建议先下载本地模型。下载完，搜文档、搜照片、识别照片里的文字就都能用了，什么都不发出去，也不花钱。

AI 桌面、自动整理、AI 标签要用对话模型，本地模型做不了。家里有一台能跑 Ollama 的电脑，可以用它；没有的话，再考虑云端。

## 本地模型 {#local}

本地模型在「本地模型」一节下载。先下载「运行环境（ONNX Runtime）」，再下载要用的模型：

| 模型 | 用途 | 大小 | 运行时约占内存 |
|---|---|---|---|
| BGE small zh v1.5 | 文本向量，语义搜索 | 约 95 MB | 300 MB |
| Chinese CLIP ViT-B/16 | 图文向量，按画面搜图 | 约 191 MB | 500 MB |
| PP-OCRv5 mobile | 识别图片中的文字 | 约 22 MB | 700 MB |

模型在 CPU 上运行，不需要显卡。

下载的文件会核对 SHA256，校验不通过的不会使用。下载中断了，下次从断点接着下。

「下载源」默认是自动选择：同时试一下各个下载源，用最快的。一个源失败了，自动换下一个。国内一般会选到 ModelScope。

服务器不能联网的，在模型的「详情」中用「离线导入」：在别的电脑上下载好文件，再从这里上传，上传后同样核对 SHA256。

不需要的模型，在「详情」中删除。

## 添加厂商 {#providers}

在「厂商」一节点「添加厂商」。预设了这些，选了以后接口地址自动填好：

OpenAI、DeepSeek、通义千问、豆包（火山方舟）、Kimi（月之暗面）、智谱、硅基流动、OpenRouter、Gemini、Ollama。

其他厂商选「其他（OpenAI 兼容）」，自己填接口地址，一般以 `/v1` 结尾。

| 字段 | 说明 |
|---|---|
| 接口地址 | 云端的地址必须是 https；局域网内的地址可以用 http |
| API Key | 在厂商的控制台创建。Ollama 等不需要 Key 的留空 |
| 每分钟请求数 | 超过后后台任务稍后再试，免得被厂商限流。0 表示不限 |
| 通过代理连接 | 使用「系统设置 › 网络」中的代理，见[网络代理](./proxy)。局域网地址始终直连 |

点「测试连接」会读一下厂商的模型列表，确认地址和 Key 是对的。这一步不调用模型，不花钱。

API Key 加密保存，保存后不会再显示出来，只显示最后 4 位。

改了接口地址的主机后，原来的 Key 作废，要重新填。这是为了防止 Key 被发到另一个地址去。

然后在厂商下面添加要用的模型，模型名可以从厂商的模型列表中选，也可以直接填。云端模型只能用作对话和文本向量。

模型的「测试」会真实调用一次，产生很少的费用。

### 本地还是云端 {#local-or-cloud}

Keepbay 按接口地址判断一个厂商是局域网的还是云端的，不让人手动勾选：

- 本机、局域网地址、`.local` 结尾的主机名等，算局域网，比如家里另一台电脑上的 Ollama
- 其余一律算云端，判断不了的也算云端

局域网的厂商和本地模型待遇一样：不计费，不受花费上限和每分钟请求数的限制，成员没有「使用云端 AI」权限也能用。

厂商列表中，局域网的显示房子图标，云端的显示云图标。

Ollama 的预设地址是 `http://127.0.0.1:11434/v1`，也就是和 Keepbay 装在同一台机器上。装在家里另一台电脑上的，改成那台电脑的局域网地址。

## 给功能选模型 {#assign}

在「使用的模型」一节，给每类模型选一个：

- **默认对话模型**：AI 桌面、自动整理、AI 标签、日期提醒都用它
- **文本向量模型**：语义搜索用
- **图文向量模型**：按画面搜图用，只能选本地模型
- **文字识别模型**：识别图中文字用，只能选本地模型

刚装好时都是"未选择"，要您选了才开始用。

不同功能可以用不同的对话模型。在「按功能指定」中单独设置，比如 AI 标签用局域网内的小模型，AI 桌面用云端的大模型。没有单独指定的，跟随默认。

换了文本向量模型或图文向量模型，要重新建立索引。重建在后台进行，建好之前仍然用原来的模型搜索，不会有一段时间搜不到。

## 关闭某项功能 {#features}

「功能」一节列出每项 AI 功能，每项一个开关，默认都开着。关闭的功能不会调用任何模型。

每项下面写着现在用的是哪个模型、在哪里处理。用云端模型的，写明会发送什么，比如 AI 桌面写"会发送你输入的文字和你让它查看的文件内容"。各项发送的内容见[隐私与安全](./privacy#ai)。

没有一键关闭全部 AI 的开关。全都不想用的，在这里逐项关掉；或者干脆不添加厂商、不下载本地模型。

## 后台功能用云端模型 {#background-cloud}

自动整理、AI 标签、日期提醒这三项会在后台自动处理文件，不是每次都有人在看着。

所以它们用云端模型时，多了一道确认：要在「后台功能用云端模型」一节中逐项打开，才会把文件信息发给厂商。

每项旁边写着现在的状态，比如"现在用 DeepSeek 的 deepseek-chat（云端），还没有允许，不会发送"。

允许是对某个厂商的某个地址给的。换了厂商，或者接口地址换了协议、主机或端口，都要重新允许。只改地址中的路径不用。

关闭后不再发送，已经有的结果保留。

用本地模型或局域网模型时，不需要允许。

## 花费上限和单价 {#budget}

花费只算云端调用。Keepbay 按您填写的单价和厂商返回的 token 数估算，实际费用以厂商的账单为准。

单价在每个模型上填：「输入单价」和「输出单价」，单位是每百万 token，不填就是 0。向量模型只有输入单价。单价没填，花费就一直显示 0，上限也不起作用。

「货币」一节选显示的货币符号，默认 ¥。这里只改符号，不换算汇率，单价和上限请按同一种货币填。

「每月花费上限」一节设置每月上限，0 表示不限，默认不限。

达到上限后，本月不再调用云端模型：

- AI 桌面提示"本月的 AI 花费已达上限"
- 向量模型在云端的，语义搜索暂时没有按意思找到的结果，按文件名和文字搜照常
- 后台任务暂停，每小时再试一次。下个月自动恢复；所有者提高上限后，最迟一小时内接着处理
- 本地模型和局域网模型不受影响

上限是在每次调用前检查的。几个调用同时进行时，可能会稍微超出一点。

花费达到上限的 80% 时通知所有者一次，达到上限时再通知一次；一次调用直接超过上限的，只发后一条。通知在「个人设置 › 通知」中可以关闭，见[通知](./notifications)。

## 调用记录 {#call-log}

每一次 AI 调用都记在「调用记录」中，从「每月花费上限」一节的「查看调用记录」进入。

每条记录有：时间、谁发起的（后台处理的写"后台处理"）、哪项功能、哪个模型、在本地还是发到了云端、发送了多少字节、多少 token、花了多少钱、用时多久、是否成功。

不保存内容本身。您问了 AI 什么、它答了什么，这里看不到。

调用失败时，会记下厂商返回的错误说明。有的厂商会在错误说明中带上一小段请求的内容。

页面顶部是本月的合计：花费、云端调用次数、每月上限。

记录保留 400 天，新的在前。目前没有筛选和导出。
