# 网络代理 {#proxy}

服务器访问外网要经过代理的，在「系统设置 › 网络」中设置。保存后立即生效，不用重启。

## 代理方式 {#modes}

| 方式 | 说明 |
|---|---|
| 环境变量 | 默认。沿用启动 Keepbay 时的环境变量 `HTTPS_PROXY`、`HTTP_PROXY`、`NO_PROXY` |
| 不使用 | 所有连接都直连，环境变量中设了代理也不用 |
| 手动设置 | 在页面上填写代理服务器 |

手动设置时，可以选 HTTP 代理或 SOCKS5 代理：

- HTTP 代理：访问 https 地址时用 CONNECT 方法
- SOCKS5 代理：域名由代理解析，服务器本地解析不了的域名也能访问

需要认证的，填写用户名和密码。密码加密保存，保存后不再显示。

改了代理服务器的地址后，原来的密码不会发给新服务器，需要的话请重新填写。

## 环境变量 {#env}

用"环境变量"方式时，代理要写在启动 Keepbay 的环境中。用系统服务运行的，在服务文件中加上：

```bash
sudo systemctl edit keepbay
```

```ini
[Service]
Environment=HTTPS_PROXY=http://192.168.1.2:7890
Environment=NO_PROXY=localhost,127.0.0.1
```

保存后重启服务：`sudo systemctl restart keepbay`。环境变量改了要重启才生效。

网络页会显示当前读到的环境变量中的代理，可以确认有没有设置对。

## 哪些连接经过代理 {#usage}

- 检查更新、下载安装包
- 专业版的联网激活和自动续期
- AI 厂商（每个厂商可以单独设置是否经过代理）
- 下载本地模型和运行环境
- 外部帐号登录：连接 Google、Microsoft、GitHub 等提供方
- 离线下载
- Bark 通知

不经过代理的：

- 局域网地址，始终直连
- 邮件通知。发件服务器要能直接连上
- BT 下载的部分连接，如 UDP tracker 和与其他节点之间的连接

Keepbay 什么时候联网、发送什么，见[隐私与安全](./privacy#outbound)。

## 测试 {#test}

填好后点「测试」，Keepbay 会用页面上填写的设置连接 GitHub 和 Hugging Face，显示能否连上和用了多少毫秒。测试只读取响应头，不保存设置。

连不上时会写明原因：

| 提示 | 原因 |
|---|---|
| 连不上代理服务器 | 代理的地址、端口不对，或者代理没有运行 |
| 代理要求认证，或用户名、密码不对 | 检查用户名和密码 |
| 代理无法连接到这个网站 | 代理本身连不上目标网站 |
| 超时 | 网络太慢，或者被防火墙拦住了 |
