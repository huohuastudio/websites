# 网络代理 {#proxy}

服务器需要经过代理访问外网时，在「系统设置 › 网络」中设置。保存后立即生效，无需重启。

## 代理方式 {#modes}

| 方式 | 说明 |
|---|---|
| 环境变量 | 默认。沿用启动 Keepbay 时的环境变量 `HTTPS_PROXY`、`HTTP_PROXY`、`NO_PROXY` |
| 不使用 | 所有连接都直连，环境变量中设置了代理也不使用 |
| 手动设置 | 在页面上填写代理服务器 |

手动设置时，可以选择 HTTP 代理或 SOCKS5 代理：

- HTTP 代理：访问 https 地址时用 CONNECT 方法
- SOCKS5 代理：域名由代理解析，服务器本地无法解析的域名也能访问

代理需要认证时，填写用户名和密码。密码加密保存，保存后不再显示。

修改代理服务器的地址后，原来的密码不会发送给新服务器，如有需要请重新填写。

## 环境变量 {#env}

使用"环境变量"方式时，代理需要设置在启动 Keepbay 的环境中。以系统服务运行的，在服务文件中添加：

```bash
sudo systemctl edit keepbay
```

```ini
[Service]
Environment=HTTPS_PROXY=http://192.168.1.2:7890
Environment=NO_PROXY=localhost,127.0.0.1
```

保存后重启服务：`sudo systemctl restart keepbay`。修改环境变量后需要重启服务才能生效。

网络页会显示当前读取到的环境变量中的代理，可以据此确认设置是否正确。

## 哪些连接经过代理 {#usage}

- 检查更新、下载安装包
- 专业版的联网激活和自动续期
- AI 厂商（每个厂商可以单独设置是否经过代理）
- 下载本地模型和运行环境
- 外部帐号登录：连接 Google、Microsoft、GitHub 等提供方
- 离线下载
- Bark 通知
- 远程文件夹：Keepbay 连接远程存储。S3 兼容存储用浏览器直连时由浏览器直接连接，不经过这里的代理

以下连接不经过代理：

- 局域网地址，始终直连
- 邮件通知。发件服务器需要能够直接连接
- BT 下载的部分连接，如 UDP tracker 和与其他节点之间的连接

Keepbay 何时联网、发送什么，见[隐私与安全](./privacy#outbound)。

## 测试 {#test}

填好后点「测试」，Keepbay 会用页面上填写的设置连接 GitHub 和 Hugging Face，显示能否连接以及耗时（毫秒）。测试只读取响应头，不保存设置。

连接失败时会显示原因：

| 提示 | 原因 |
|---|---|
| 无法连接代理服务器 | 代理的地址或端口错误，或者代理没有运行 |
| 代理要求认证，或用户名、密码不正确 | 检查用户名和密码 |
| 代理无法连接到这个网站 | 代理本身无法连接目标网站 |
| 超时 | 网络太慢，或者被防火墙拦截 |
