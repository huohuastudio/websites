# 备份和维护 {#backup}

Keepbay 每天自动备份一次数据库，保留最近 7 份。备份、日志和诊断信息都在「系统设置 › 维护」中。

在网页上更新 Keepbay 也在这一页，见[升级](./upgrade)。

## 备份内容 {#what}

备份的是 Keepbay 的数据库：文件索引、标签、智能文件夹、分享链接、整理记录、设置和帐号。

**您的文件本身不在备份范围内。** 它们在您自己的文件夹里，Keepbay 只是建立了索引。请用 NAS 的快照、rsync 或其他备份工具备份它们。

数据库丢失时，文件不受影响，但需要重新添加文件夹、重新扫描，标签和设置也要重新设置。文件丢失时，数据库备份无法恢复文件。

数据目录中的 `secret.key` 也不在备份中，请另外保管一份，原因见[下文](#secret-key)。

## 自动备份 {#auto}

| 设置 | 说明 |
|---|---|
| 频率 | 每天（默认）、每周或关闭。在服务器时区的凌晨 3 点后进行 |
| 保留份数 | 默认 7 份，可以设 1 到 60 份。自动备份和手动备份合计，更早的自动删除 |
| 备份目录 | 留空时是数据目录下的 `backups/`。可以改到其他磁盘，需要填写完整路径，目录必须已经存在并且可写 |

备份目录不能放在添加给 Keepbay 的文件夹里。数据库中有全部帐号和设置，如果放在挂载的文件夹中，有权限的成员就能直接下载。

备份失败时，1 小时后重试，同时通知所有者，每天最多一条。

备份文件的名称带有日期和时间，比如 `keepbay-auto-20261113-030012.db`。

## 立即备份 {#manual}

在维护页点「立即备份」，或者在服务器上运行：

```bash
sudo -u keepbay /opt/keepbay/keepbay db:backup
```

进行较大的改动之前，比如移除文件夹、批量整理，可以先手动备份一份。

## 备份列表 {#list}

维护页列出所有备份，分四类：

- 自动：每天或每周的自动备份
- 立即备份：手动进行的备份
- 升级前：新版本需要升级数据库时，升级前自动进行的备份
- 恢复前：用备份恢复时，被替换下来的数据库

网页上不能下载备份。数据库中有全部的索引和设置，我们不希望它能从浏览器中直接下载。如有需要，请在服务器上直接复制备份目录中的文件。

## 恢复 {#restore}

恢复只能在服务器上用命令行进行，网页上不能恢复：

```bash
sudo systemctl stop keepbay
sudo -u keepbay /opt/keepbay/keepbay db:restore    # 在列表中选一份备份
sudo systemctl start keepbay
```

恢复前，现在的数据库会先保存为一份"恢复前"的备份，如果恢复有误，可以用它还原。

用旧版本的备份恢复时，启动后数据库会自动升级到当前版本。

命令的详细说明见[命令行](./cli#db-restore)。

## secret.key {#secret-key}

AI 厂商的 API Key、通知和代理的密码、两步验证的密钥、远程存储的访问密钥，在数据库中是用数据目录中的 `secret.key` 加密保存的。

`secret.key` 不放进数据库备份。这样备份文件被他人复制时，里面的 Key 和密码仍然是密文。

用备份恢复到新的服务器时，请把原来的 `secret.key` 一并复制过去。缺少它时：

- AI 厂商的 API Key、通知渠道和发件服务器的密码，要重新填写
- 开启了两步验证的帐号，要用恢复码登录
- 远程文件夹无法连接，访问密钥也无法修改，只能移除后重新添加。标签、AI 的处理结果和成员的授权会随之删除

建议把整个数据目录一起备份和迁移，见[安装](./install#data-dir)。

## 日志 {#logs}

日志写在数据目录的 `logs/keepbay.log` 中，超过 5 MB 时换用新文件，保留最近 3 个旧文件。维护页显示日志文件的位置。

以系统服务运行的，也可以用 journalctl 查看：

```bash
sudo journalctl -u keepbay -f
```

## 诊断信息 {#diagnostics}

遇到问题需要求助时，在维护页的「诊断信息」中点「生成」，下载一个诊断文件发给我们。

诊断文件包含：版本和系统信息、依赖检测结果、设置、最近 2000 行日志、数据库检查结果、文件夹和任务的统计。

不包含 `secret.key`、密码、会话、API Key、授权证书和您的文件内容，日志中的令牌和密码也会被清除。

「隐藏路径、文件名和网址」默认打开，会把它们换成 `[路径1]` 这样的占位符。

下载前可以在页面上展开查看全部内容，确认其中没有不希望发送的信息。

## 数据库检查 {#db-check}

怀疑数据库有问题时，在服务器上运行：

```bash
sudo -u keepbay /opt/keepbay/keepbay db:check
```

数据库较大时需要几分钟。发现问题时，可以用最近一份正常的备份恢复，见[命令行](./cli#db-check)。
