# 文件夹 {#folders}

Keepbay 管理的是您服务器上已有的文件夹。所有者在「系统设置 › 存储」中把文件夹"挂载"进来，Keepbay 读取文件、建立索引，文件原样留在原处。

本页讲挂载文件夹的设置、离线状态和忽略规则。第一次添加文件夹的步骤见[首次设置](./setup#add-folder)。

文件在 S3 兼容的对象存储、WebDAV 或能用 SSH 登录的服务器（SFTP）上的，专业版可以直接添加，见[远程文件夹](./remote-folders)。在各种网盘或者另一台 NAS 上的，先同步或挂载到本地，见[云盘](./cloud-storage)。

## 添加文件夹 {#add}

点「添加文件夹」，填写服务器上的绝对路径，比如 `/srv/photos`。路径要手动输入，没有目录浏览。

| 字段 | 说明 |
|---|---|
| 服务器上的路径 | 文件夹的绝对路径，添加后不能修改 |
| 显示名称 | 显示在侧栏中，默认用文件夹名 |
| 访问方式 | 读写，或只读 |
| 处理程度 | 完整处理（默认）、只认文件或只建目录，见[处理程度](#processing) |
| 定期补扫间隔 | 默认 360 分钟，可以设 15 到 10080 分钟 |
| 图标 | 显示在侧栏、面包屑和文件夹列表中，可以选图标和颜色 |

添加前，请先授予 `keepbay` 用户这个文件夹的权限，只需运行一条命令，见[安装](./install#permissions)。如果没有提前授权，页面会显示填好路径的命令，可以直接复制。

路径填好后，Keepbay 会检查它所在的磁盘类型。如果是网络盘或 rclone 等 FUSE 挂载，访问方式会预先选为只读，表单中还会说明添加后读取文件内容产生的流量。哪些磁盘会这样处理，见[添加时的检查](./cloud-storage#detect)；流量的估算和降低方法，见[挂载的注意事项](./cloud-storage#caveats)。

Keepbay 还会检查能否写入。只能读取的文件夹，访问方式会自动选为只读，路径下说明原因并给出授权命令。仍选读写时不能添加。文件夹所在的文件系统是只读挂载的（如光盘、只读挂载的网络盘），只能以只读方式添加。

以上两种情况，您已经手动选择过访问方式的，不会被更改。

以下路径不能添加：

- 不存在或者不是文件夹
- 和已经添加的文件夹重叠，也就是一个在另一个里面
- 和 Keepbay 的数据目录、备份目录重叠

添加后立即开始扫描。先建立文件列表，这时就能浏览和按文件名搜索了；然后在后台识别文件、生成缩略图、提取文字，具体做哪些取决于[处理程度](#processing)。进度在列表中和侧栏的「更多 › 后台任务」中显示。

## 只读和读写 {#read-only}

以只读方式添加的文件夹，Keepbay 只读取和建立索引，不做任何写入：不能上传、移动、改名、删除，也不会在里面放回收站。

这个限制在最底层的文件访问模块中实现，即使上层代码出错，也无法写入。

如果您还在试用 Keepbay，或者文件夹中是重要资料，建议先用只读方式添加。确认效果后，在「修改设置」中改为读写。改为读写时同样会检查能否写入，不能写入时不保存，并给出授权命令。

### 不能写入 {#write-denied}

读写的文件夹之后可能变得不能写入，比如所有者或权限被改动，或文件系统变为只读挂载。Keepbay 定期检查时发现这种情况，会在以下位置标出：

- 首页的文件夹卡片，状态写"不能写入"
- 侧栏中文件夹名称的后面写"不能写入"
- 「系统设置 › 存储」中这一行的图标标红，状态写"不能写入"，下方说明原因和处理方法

打开这个文件夹时，「新建」「上传」等按钮不可用。按对应的快捷键时，页面说明原因：所有者可以点「查看存储设置」进入存储页处理，成员的提示是请联系所有者。

处理方法是按存储页的说明给 Keepbay 写入权限，或者把文件夹改为只读。文件系统变为只读挂载的，授权无法解决，请改为只读。

检查只针对添加的文件夹本身（最上一级），不检查其中的子文件夹。子文件夹可能另有权限，照常可以写入；不能写入时，写操作会报错。成员被授权的是子文件夹时，不显示这个标记。

## 处理程度 {#processing}

每个文件夹可以选择 Keepbay 读取多少内容。添加时在表单中选择，以后在文件夹的设置中修改。本机文件夹默认完整处理，[远程文件夹](./remote-folders#process)默认只建目录。

| 处理程度 | 读取的内容 | 能做的事 |
|---|---|---|
| 完整处理 | 多数文件完整读取一次，生成缩略图、提取文字时可能再读取 | 缩略图、搜索文字、AI、查找相同的文件 |
| 只认文件 | 每个文件开头、中间、结尾各 64 KB，192 KB 以内的整份读取 | 识别类型、查找相同的文件；没有缩略图，不提取文字 |
| 只建目录 | 不读取 | 按名称浏览、搜索、分享；类型按扩展名判断 |

挂载的网盘、按流量计费的存储，可以用后两档减少读取，见[挂载的注意事项](./cloud-storage#caveats)。

只认文件时，如果有大小和抽样内容都相同的另一份，Keepbay 会完整读取这几份，确认是否相同。

只建目录时，浏览器能直接显示的图片（SVG 除外）、视频、音频和 PDF，打开时读取原文件；[压缩包](./files#archive)也可以照常查看。其他文件只能下载。还没有识别的文件，不能通过加了[水印](./share#watermark)的分享链接查看和下载。

改为更完整的程度后，Keepbay 在后台补做已有的文件。改为更低的程度时，已有的缩略图、文字等保留；这些已经完整处理过的文件，在 Keepbay 升级处理方式时仍可能重新读取。

子文件夹可以单独设置，这项设置只有所有者能看到。选中一个文件夹（不选时是当前所在的文件夹），在信息面板的「处理程度」一节中选「跟随上级」或三档之一。例如整个文件夹只建目录，只给照片子文件夹完整处理。文件夹的根目录没有「跟随上级」，与文件夹设置中的是同一项。

## 修改和移除 {#edit}

列表中每个文件夹的菜单中，有「立即扫描」「修改设置」和「空间分析」，空间分析的说明见[空间分析](./space)。显示名称、访问方式、补扫间隔、图标都可以改，路径不能改。

拖动文件夹左侧的把手，可以调整它们在侧栏中的顺序。图标和顺序对所有成员都相同。

需要更换路径时，先移除，再用新路径添加。

移除文件夹只删除 Keepbay 中的索引，磁盘上的文件不受影响。但是文件上的标签、AI 的处理结果会随索引一起删除，重新添加后需要重新打标签。成员对这个文件夹的授权也会删除。

## 发现文件的变化 {#watch}

本地磁盘上的文件变化，Keepbay 通过系统的文件监听可以立即发现，通常几秒内就会更新索引。在 NAS 文件管理、Syncthing、相册程序中做的改动同样如此。

SMB、NFS 等网络磁盘无法收到变化通知，需要依靠定期补扫，默认每 6 小时一次。网络磁盘上的文件夹，可以把补扫间隔改短一些。需要立即更新时，点「立即扫描」。

文件夹很多时，可能超过系统的文件监听上限，存储页会提示"文件夹太多，部分文件夹的变化无法立即发现"。调大上限的方法见[常见问题](./faq#inotify)。

## 离线状态 {#offline}

Keepbay 会定期检查每个文件夹是否正常。发现异常时，把文件夹标记为离线，停止写入和清理索引，等您处理。

| 原因 | 说明 |
|---|---|
| 找不到文件夹 | 可能是硬盘没有连接，重新连接后自动恢复 |
| 磁盘已更换 | 文件夹所在的磁盘和之前不同，可能是硬盘未挂载，看到的是挂载点下面的空目录 |
| 文件夹突然变空 | 可能是硬盘未挂载 |
| 无法读取 | 权限变了，请检查文件夹的权限 |
| 路径指向了别处 | 路径中的符号链接被改动，为安全起见暂停使用 |

我们这样设计，是因为 USB 硬盘未挂载时，挂载点 `/mnt/usb` 仍然存在，只是一个空目录。这时如果当成"文件全部删除"，就会清空索引，丢失所有标签；如果往里写入文件，硬盘挂载后，这些文件会被遮盖，无法访问。

状态为"磁盘已更换"时，把原来的硬盘重新连接，检查通过后会自动恢复。如果确实更换了新硬盘，点「确认恢复」。

状态为"文件夹突然变空"时，原来的内容重新出现并通过检查后，会自动恢复。如果确实清空了文件夹，点「确认恢复」。

文件夹离线期间，索引、标签、AI 结果都原样保留。硬盘重新连接后即可继续使用。

## 缺失的文件 {#missing}

扫描时发现文件已不存在，Keepbay 不会马上删除它的记录，而是标记为缺失，30 天后才清除。

如果文件在这 30 天内重新出现，比如您把它从别处移了回来，标签等信息仍然保留。

一次扫描发现大量文件不见时，Keepbay 会暂停清理，存储页提示"上次扫描发现大量文件缺失"。确认这些文件确实已删除后，再点「确认继续清理」。

## 忽略规则 {#ignore}

匹配忽略规则的文件和文件夹不建立索引，不出现在列表和搜索结果中，磁盘上的文件不受影响。

内置规则始终生效，跳过各系统和 NAS 生成的杂项文件。另有四类默认跳过，可以关闭：macOS 照片图库、开发目录、其他应用的资料库、同步软件的缓存。完整清单见[搜索](./search#skipped)。

所有者可以添加自己的规则：

- 名称可以用通配符，`*` 匹配任意字符，`?` 匹配一个字符，比如 `*.tmp`、`node_modules`
- 生效范围可以是全部文件夹，也可以是某一个文件夹

## 回收站 {#trash}

存储页的「回收站」一节可以设置保留时间，见[回收站和撤销](./trash#retention)。

## 媒体处理 {#media}

「系统设置 › 媒体处理」显示缩略图和预览所需的工具是否可用：

- ffmpeg、ffprobe：视频缩略图、TS 视频的在线播放和 HEIC 照片需要，HEIC 要 7.1 及以上版本；浏览器不能播放的[实况照片](./files#live)视频由它转换，「支持的格式」中的「实况照片的视频转码」一行显示是否可用
- 安全限制：处理照片和视频的子进程是否被隔离。内核不支持系统调用过滤时，这里还有"照样处理照片和视频"的开关

安装或升级 ffmpeg 后，点「重新检测」，不需要重启。之前未处理的文件会自动补充处理。

ffmpeg 不在 PATH 中时（如群晖套件装的），在「ffmpeg 路径」中填写 ffmpeg 程序的完整路径（1.0.0-beta.15 起）。「ffprobe 路径」选填：留空时先找 ffmpeg 所在目录中的，再在 PATH 中查找；两者分开安装时填写 ffprobe 程序的完整路径。保存前会先检测，ffmpeg 和 ffprobe 都能运行才保存，不能用时说明原因。离线下载视频时合并音视频也使用这个 ffmpeg。

处理照片和视频为什么要隔离，见[隐私与安全](./privacy#sandbox)。
