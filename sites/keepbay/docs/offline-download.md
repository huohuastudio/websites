# 离线下载 {#offline-download}

离线下载由服务器代为下载文件：提供网址、磁力链接或种子文件，服务器下载完成后放入您的文件夹。下载期间您的电脑可以关机。

有可用的 yt-dlp 时，还可以下载视频网站的视频。yt-dlp 可以由 Keepbay 安装和更新。

## 新建下载 {#new}

在侧栏的「更多 › 离线下载」页点「新建下载」，或者在页头的「新建」菜单中选「离线下载…」。

可以下载的有：

- http、https 网址
- 磁力链接
- 种子文件，用「选择种子文件…」上传，最大 10 MB

一次可以粘贴多个链接，每行一个，最多 50 个。

「保存位置」默认是收件箱，可以改为其他文件夹。尚未设置收件箱时，需要先选择一个位置。

BT 下载获取到种子信息后，可以在任务的菜单中点「选择文件…」，只下载需要的那几个文件。

## 下载视频网站的视频 {#yt-dlp}

勾选「按视频网站下载」，Keepbay 会调用 yt-dlp 下载。只支持单个视频，不支持直播和包含多个视频的页面。单个视频超过 6 小时未下载完成，记为失败。

yt-dlp 不随 Keepbay 附带。所有者可以在「系统设置 › 离线下载」的「由 Keepbay 安装」一节点击「安装」：

- Keepbay 从 GitHub 上 yt-dlp 的官方发布页下载对应平台的版本，按官方的校验值校验、确认能运行后，保存在数据目录的 `tools/` 中
- 下载 YouTube 的视频还需要 Deno（JavaScript 运行时，约 40 MB），在同一节中安装。没有 Deno 时，YouTube 的视频可能缺少部分格式或无法下载
- 打开「自动更新」时（默认打开），每天检查一次新版本并自动更新。视频网站经常改版，旧版本的 yt-dlp 可能很快失效，建议保持打开。也可以点击「检查更新」立即检查
- 安装和更新属于离线下载，默认不经过代理。提示连不上 GitHub 时，在「系统设置 › 网络」中设置代理，并在「使用代理的功能」中打开「离线下载」

也可以自行安装 yt-dlp，例如：

```bash
pipx install yt-dlp
```

Keepbay 按以下顺序查找 yt-dlp：「视频网站」一节中填写的 yt-dlp 路径、Keepbay 安装的、PATH 中的。自行安装后在「视频网站」一节点击「重新检测」，无需重启 Keepbay。自行安装的 yt-dlp 需要自己更新。

## 管理任务 {#tasks}

「离线下载」页列出所有任务和进度，可以暂停、继续、取消。取消时，已下载的部分会被删除。

暂停后，或者 Keepbay 重启后，下载从断点继续，已下载的部分不会丢失。

网络出错时会自动重试，包括首次在内最多尝试 5 次。仍然失败时，可以点「重试」，从头开始下载。

完成和取消的任务可以「清除」，失败的保留，方便重试。未清除的已结束记录保留 30 天。

每个人最多同时有 50 个未结束的下载。

## 下载完成后 {#finish}

下载过程中，文件放在目标文件夹中一个隐藏的临时文件夹里，全部下载完成后才改名放进目标文件夹，因此不会出现下载不完整的文件。

视频网站的下载有所不同：yt-dlp 先下载到数据目录的 `downloads/` 中，完成后再复制到目标文件夹。下载大视频时，数据目录所在的磁盘也需要预留足够的空间。

与目标文件夹中已有的文件重名时，不会覆盖，新文件命名为 `名称 (1)`。

## 设置 {#settings}

所有者在「系统设置 › 离线下载」中设置：

| 设置 | 说明 |
|---|---|
| 同时下载 | 默认 3 个，最多 10 个，其余的排队 |
| 速度上限 | 所有下载合计的速度上限，默认不限 |
| 单个大小上限 | 超过时停止下载，记为失败，默认不限 |
| BT 监听端口 | 1024–65535，留空时在首次下载时自动选择 |
| BT 端口映射 | 用 UPnP 在路由器上自动打开端口，可以连接更多来源，但会把这台设备的这个端口暴露到外网 |
| BT 上传速度上限 | BT 下载过程中给其他节点上传的速度 |
| 附加 tracker | 新建 BT 任务时自动加上的 tracker，默认为空，见[附加 tracker](#trackers) |
| tracker 订阅 | 按地址订阅公共的 tracker 列表，按更新间隔自动更新，默认不订阅，见[tracker 订阅](#tracker-subs) |
| yt-dlp 路径 | 选填。留空时使用 Keepbay 安装的，没有时在 PATH 中查找，见[下载视频网站的视频](#yt-dlp) |
| 自动更新 | Keepbay 安装的 yt-dlp 和 Deno 每天检查一次新版本 |

下载完成后不做种，也就是不再给其他人上传。这一项不能修改。

离线下载默认不经过代理。服务器要经过代理才能访问下载地址时，比如国外的视频网站，在「系统设置 › 网络」中设置代理，并在「使用代理的功能」中打开「离线下载」，见[使用代理的功能](./proxy#usage)。

BT 下载与其他用户之间的连接、DHT 始终直连，不经过代理，也不消耗代理的流量。

### 附加 tracker {#trackers}

磁力链接自带的 tracker 较少或已失效时，BT 下载可能很久都开始不了。在「系统设置 › 离线下载」的「附加 tracker」一节中填写可用的 tracker，可以更快找到下载来源。

每行填一个地址，支持 http、https 和 udp，如 `udp://tracker.example.org:6969/announce`。不能是局域网或本机的地址。点「保存」后，空行和重复的行会去掉，最多保存 100 个。有不正确的行时，提示第几行和原因。

填写后，之后新建的 BT 任务自动加上这些 tracker：

- 种子文件：公开的种子新建任务时即加上
- 磁力链接：取到种子信息、确认不是私有种子后才加上。所以在"取种子信息"这一步，附加的 tracker 不起作用
- 私有种子（PT 站的种子）不加。否则会违反站点的规则，帐号可能被封禁
- 已经有的任务不变

默认为空，Keepbay 不预置公共 tracker 列表。公共 tracker 经常失效，手动填写的需要您自己维护，失效的请删除。也可以订阅公共的 tracker 列表，自动更新，见[tracker 订阅](#tracker-subs)。

:::warning
tracker 能看到下载者的 IP 地址和正在下载的种子。填写的 tracker 越多，能看到这些信息的服务器越多。请只填写您信任的 tracker。
:::

附加的 tracker 与种子自带的连接方式相同：http、https 在离线下载经过代理时使用代理，https 校验证书，udp 直接连接。

### tracker 订阅 {#tracker-subs}

网上有公开维护的 tracker 列表，维护者会定期去掉失效的地址。在「系统设置 › 离线下载」的「tracker 订阅」一节中添加列表的地址，Keepbay 按更新间隔自动取回其中的 tracker。

取回的 tracker 与手动填写的附加 tracker 合并，去掉重复的，再加到之后新建的 BT 任务中。规则与[附加 tracker](#trackers) 相同：私有种子不加，磁力链接确认不是私有种子后才加，已有的任务不变。

默认不订阅。添加订阅有两种方式：

- **添加订阅**：填写订阅地址
- **添加常用的订阅**：填入 [ngosang/trackerslist](https://github.com/ngosang/trackerslist) 的 trackers_best 列表，地址为 `https://cdn.jsdelivr.net/gh/ngosang/trackerslist@master/trackers_best.txt`。这里用的是 jsDelivr 的地址，因为 raw.githubusercontent.com 在国内经常无法连接

订阅地址只支持 http、https，不能是局域网或本机的地址，最多 10 个。添加和移除后立即保存。

更新间隔可选每 6 小时、每 12 小时、每天、每周，默认每天。点「立即更新」，马上取回全部订阅。

每个订阅显示取到的 tracker 个数和上次更新的时间。更新失败时显示原因，继续使用上次取到的列表，1 小时后再试。

订阅地址返回的内容按以下规则读取：

| 项目 | 要求 |
|---|---|
| 格式 | 每行一个 tracker；`#` 开头的行是注释，空行忽略 |
| 每一行 | 与手动填写的检查相同：只支持 http、https 和 udp，不能是局域网或本机的地址。不正确的行跳过 |
| 内容大小 | 最大 256 KB，超过时记为更新失败 |
| 个数 | 每个订阅最多取前 200 个；与手动填写的合计最多 500 个，手动填写的在前 |

取订阅列表默认经过代理，可以在「系统设置 › 网络 › 使用代理的功能」中关闭「tracker 订阅」，见[使用代理的功能](./proxy#usage)。这项只影响取列表，BT 任务连接 tracker 时仍按「离线下载」的设置。

:::warning
上面关于 tracker 的提醒同样适用于订阅的列表：tracker 能看到下载者的 IP 地址和正在下载的种子，而订阅的列表中有哪些 tracker 由列表的维护者决定。请确认来源可信后再订阅。
:::

## 成员使用离线下载 {#members}

成员默认不能使用离线下载，需要所有者在成员的权限页打开「离线下载」，见[成员和权限](./members#features)。

离线下载会让这台设备按他人提供的链接访问外网，还会占用磁盘空间和带宽，所以默认关闭。

## 安全 {#security}

离线下载只能访问公网地址，不能访问局域网和本机的地址，比如路由器的管理页、NAS 的管理页。

这个检查在建立连接时进行，按实际连接的 IP 判断。网址跳转到内网、域名解析到内网，都会被拦截。

BT 下载同样不会连接内网地址。

Tailscale 的地址段（100.64.0.0/10）也在拦截范围内。局域网或 Tailscale 网络中的文件，建议直接把所在的文件夹添加到 Keepbay。

离线下载经过代理时（在「系统设置 › 网络」中设置了代理，并在「使用代理的功能」中打开了「离线下载」），域名经代理交给公共 DNS（Cloudflare、Google）解析，用的是加密的 DNS 查询。本机的 DNS 被污染、把网站解析到错误的地址时，也能正常下载。代理不通或公共 DNS 查不到时，改在本机解析。

服务器所在网络的代理软件（Clash 等，常装在路由器上）使用 fake-ip 模式时，域名在本机会被解析到 198.18.0.0/15。这一段不是公网地址，离线下载不经过代理时，所有离线下载都会失败，原因显示为"链接指向局域网或本机地址"。处理方法有两种：

- 在「系统设置 › 网络」中设置代理，并在「使用代理的功能」中打开「离线下载」。域名改由公共 DNS 解析，不受 fake-ip 影响
- 在代理软件中把运行 Keepbay 的设备排除在 fake-ip 之外：按设备的 IP 设为直连解析，或改用返回真实地址的模式（如 redir-host）

更多说明见[隐私与安全](./privacy#offline-download)。
